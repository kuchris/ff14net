## Findings

- **No Deucalion repair is needed.** Official Deucalion 1.5.1 already contains
  the receive signature `E8 $ { ' } 4C 8B 47 10 44 8B 4F 1C` that this repo
  patched into 1.5.0 for 7.57. The old 1.5.0 pattern is gone from the DLL.
- The 2026.11.03 executable has exactly three matches for that signature
  (file offsets `0x1d1da2b`, `0x1d27fe4`, `0x1d69054`) and none for the old one.
- The 3.0.3.4 plugin's embedded Machina checksum is the official 1.5.1 SHA256,
  so the pair loads without checksum changes.
- 3.0.3.4 ships the 7.57 (`2026.10.16`) Global opcodes: 26/26 equal
  `global/7.57_2026.10.16.txt` and 0/26 equal the 7.58 table. Without a
  patch it uses wrong opcodes on 7.58.

## Bundle

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\build_act_bundle_20261103.ps1
```

The script checks the three input hashes, the signature count and the
plugin/Deucalion checksum pairing. It then patches the 26 opcodes with
`ActPluginPatch patch-file`, reads them back, and checks that the pairing still
holds. The previous `tools/third_party/patch/` contents are backed up under
`build/20261103-bundle/before-*` before they are replaced.

## Install and live check

The desktop already has the official Deucalion 1.5.1, so only the plugin changes:

1. Close ACT and back up `FFXIV_ACT_Plugin.dll` from the plugin folder.
2. Copy `tools/third_party/patch/FFXIV_ACT_Plugin.dll` over it.
3. Start ACT, then run:

   ```powershell
   uv run python scripts\deucalion_probe.py --seconds 8 --output captures\deucalion_health_20261110_after.json
   ```

4. Attack a training dummy and check for ACT type `21`/`22` damage events and
   nonzero DPS.

Live status: **not tested yet.** The 7.58 opcodes come from the community and
have not been checked against live packets.
